## 一、两个已拍板的决定（别再推翻重议）

### 1. 路线：v3 是唯一主线（方案 A）

`main` 只做安全修复 + `track-upstream.yml` 自动跟上游，v3 发版后归档为 v2 分支。

依据（不是偏好，是举证）：
- 五个已关 issue 是被**架构性消除**的，不是修出来的：`#39` 拷 U 盘几万小文件太慢、`#27` 缺符号链接、
  `#43` 装完启动失败、`#29` 装完无法创建文件、`#37` 装不了。同一个病根：运行时住在 U 盘上。
- `v2.1.15~17` 三个包**发出去就是开不了机的**（`918e3ca`：内置 Node 跑不动所 pin 的内核）。
  v2 的修法是让客户重下 245.8 MB 重拷；v3 是换个 seed 或 `runtime.activate --rollback` 改指针。
- exFAT 强制在 v2 上永远删不掉，而出厂 U 盘默认就是 exFAT，这是每个新客户的第一道坎。

**必须同时记住的反面事实**：当前仅剩的 3 个 open issue（`#61` 加模型、`#51` OpenRouter、`#47` 合作咨询）
**没有一个是瘦壳架构解决的**。v3 的价值是「防复发」和「防坏包无法挽救」，不是在解今天手上的待办。
拿 v3 当「做完就没 issue 了」的银弹会失望。

### 2. 对外口径：明说 + 可清理 + 可切换

详见计划 §2「对外口径与 portable-strict 模式」。三句话版本：
默认在本机建约 850 MB 缓存并**明着告诉客户**；给一键清理（`runtime.host.purge`）；
给开关切 portable-strict（全部装 U 盘、零残留，慢）。

> ⚠️ 待确认的一处措辞歧义：用户原话是「给一个开关，可以选择**全部安装**」。
> 本文按「全部装在 U 盘上 = portable-strict」理解，因为它对应的是「不留痕」这个诉求，
> 且计划里本就有这个模式。若用户本意是「全部装到本机（连 data 也搬走）」，那是第三种模式，
> 现有 `Windows-Install.bat` 已经在做类似的事，需要单独确认后再动。**动手前先问一句。**

## 四、别踩的坑

- **Windows 解 tar.gz 必须点名 `%SystemRoot%\System32\tar.exe`**（bsdtar）。PATH 上的 GNU tar
  把 `C:\` 当远程主机，报 `Cannot connect to C:`。用 `kernel-manager.mjs` 的 `tarBinary()`。
- **zip 走 `Expand-Archive`**，对 node_modules 深路径有 MAX_PATH 风险，所以**内核 seed 定 tar.gz**，
  Node 官方包路径短用 zip 没事。
- **Node 版本必须满足内核的 `engines.node`**（当前 `>=22.22.3 <23 || >=24.15.0 <25 || >=25.9.0`）。
  通道现钉 `22.23.2` / minimum `22.22.3`。`build-seed.mjs` 装完内核会拿真 `engines` 卡这两个值，
  不满足直接构建失败 —— `track-upstream.yml` 每天自动升 `OPENCLAW_VERSION`，没这道卡就会发出
  「解压即用、但一启动就报 Node 版本不对」的包（v2.1.15~17 就是这么出去的）。
- **`node --test tests/` 目录模式在 Node 22 上报 MODULE_NOT_FOUND**，一律用 `node --test "tests/*.test.mjs"`。
- **CLI 保留标志会吞动作参数**：`uclaw.mjs` 里 `version` 等是保留标志，现已改成「动作声明了同名输入就归动作」。
  加新动作时若用了 `json`/`quiet`/`yes` 这类名字，先看一眼 `coerceInput`。
- **`portable/vendor/` 已在 .gitignore**，seed 是现产的，几百 MB，绝不能进 git。
- **prune 名单在 `build-seed.mjs` 的 `PRUNE_DIRS`**（`@node-llama-cpp` / `node-llama-cpp`，
  不删则内核树 1466 MB、tar.gz 532 MB）。以后 `release.yml` 改成调这个脚本时，
  它自己那段 find + prune 要删掉，认这里当唯一真相源。
- 代理 `127.0.0.1:7897` 会抖，`gh` 偶发 TLS handshake timeout，重试即可。
